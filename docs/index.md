## One Run Is Not Enough: How Much AI Agent Results Vary <br>in Data Science, an XGBoost Optimization Study

#### by Szilard Pafka and Eduardo Ariño de la Rubia

**TL;DR** We used AI agents powered by three different large language models (LLMs) to autonomously tune an XGBoost model, running each LLM 10 times with the same setup and the same instructions. On average, the agents considerably improve the starting model, and the three LLMs rank clearly against one another. But results vary a lot from run to run, so much that the ranges of the different LLMs overlap. One run of a given setup is therefore not enough, either to judge how well an agent performs or to compare LLMs.

---

In our [previous project](https://szilard.github.io/xgboost-autoresearch/) we showed that AI coding agents can automate much of a data scientist's trial-and-error work: they research ideas, engineer features, tune the hyperparameters of an XGBoost model, and keep what works. However, the results we presented came from a single run of a single agent, and AI agents are not deterministic: given the same task twice, the same agent will try different ideas, in a different order, and end up with a different model. So a single run is just one sample from a wide range of possible outcomes. It does not necessarily tell us how good a setup really is, or whether one LLM is better than another. To answer those questions, we rebuilt the project into a minimal, self-contained building block for a single run, and added an orchestrator that runs it many times, fully automatically.

The task is the same as before: predict whether a flight will be delayed, using airline data. The agent has 2 hours to improve a starter XGBoost model on its own. It searches the web for ideas, edits the code to engineer new features and tune the hyperparameters, keeps the changes that improve the AUC (area under the ROC curve) on an evaluation dataset and discards the rest. Every model the agent keeps is then scored on a separate holdout dataset that the agent never sees, so we measure how well the models really generalize, not just the score the agent was optimizing. (For simplicity, the holdout set is a random sample of the same year's flights, so this tests generalization to unseen flights, not to future dates.) Compared to the first project, the setup ([xgboost-autoresearch-minimal2](https://github.com/szilard/xgboost-autoresearch-minimal2)) is simpler and more standardized. The orchestrator ([xgboost-autoresearch-minimal2-runs](https://github.com/szilard/xgboost-autoresearch-minimal2-runs)) runs the experiment repeatedly without any human steering: each run starts in a fresh, isolated Docker container with identical instructions, and automatic checks afterwards verify that the agent followed the rules. With this, we ran three OpenAI models, gpt-6-luna, gpt-6-sol and gpt-6-astra (Luna, Sol and Astra for short), at maximum reasoning effort, 10 times each.

<img src="holdout_auc.png" style="width: 700px">

The first plot shows the final holdout AUC of each run (higher is better; the starter model scores 0.7155). Each dot shows the holdout AUC of one 2-hour run's selected model, the kept model with the highest evaluation AUC (hollow dots mark runs in which the agent glanced at a data preparation script it was not supposed to read, without accessing any holdout data; their results are in line with the rest). The black dot with whiskers marks each LLM's mean with its 90% confidence interval, which shows how precisely we know the average, while the short vertical ticks mark the 10th and 90th percentiles, which show the spread of single runs. On average the three LLMs rank clearly: Astra comes first, then Sol, then Luna. But the runs of each LLM are spread widely. The gap between Luna's best and worst run is about 0.025 AUC, more than half of the typical improvement the agents achieve over the starter model; Sol's range is about half of that. The ranges also overlap: Luna's best run beats the worst runs of both Sol and Astra.

<img src="holdout_auc_pairwise.png" style="width: 700px">

The second plot shows how often a single run would rank two LLMs wrong. For each pair of LLMs, it gives the probability that a randomly picked run of the better LLM beats a randomly picked run of the other one. Astra beats Luna in 97% of pairings, but Sol still beats Astra in about 23% of pairings, and Luna beats Sol in about 12%. So comparing two LLMs based on a single run each would give the wrong answer surprisingly often, even when one of them is clearly better on average.

<img src="holdout_auc_path.png" style="width: 700px">

The third plot shows where this variation comes from. Each line traces one run, experiment by experiment, and each step up is a change the agent kept. Nearly all runs start with the same obvious move, raising the number of trees, which lifts the AUC to about 0.73. After that the paths diverge: some runs find a key idea early and climb quickly, while others get stuck on a plateau for dozens of experiments. Part of the gap between the LLMs comes down to a single idea: every Sol and Astra run used the exact calendar date of the flight as a feature, which lets the model learn which days were unusually disrupted (this works because in our simple setup, the training, evaluation and holdout datasets are non-overlapping random samples of the same year's flights, so they share the same days), while Luna's runs never added an explicit calendar-date feature and relied mostly on tuning hyperparameters instead. But a good idea alone does not guarantee a good result: Sol's weakest run also used the date. How far a run gets therefore depends partly on luck: which ideas the agent happens to try, in what order, and how well it follows them up.

In conclusion, today's AI agents consistently deliver considerable improvements on data science tasks like this one, but the size of the improvement varies a lot from run to run, even with identical setup and instructions. This has two practical consequences. First, to compare agents, LLMs, prompts or any other part of the setup, one run is not enough. You need repeated runs and should look at the distribution of the results, not a single number. Second, if you just want a good model, it pays to run the agent several times and pick the best run, judged on data the agent has not seen. Both repositories are open source, so you can use them to test your own agents, LLMs and setups, ideally with more than one run each.
